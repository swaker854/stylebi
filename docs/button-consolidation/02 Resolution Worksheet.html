4 · R3 — Danger (1 row) + the bigger finding

There is exactly one btn-danger in the entire app.

SiteResolution
viewer-app.component.html:22 Unlabelled, no sibling context captured. Confirm placement → CTA (.btn-primary.is-danger) or inline (.btn-ghost.is-danger) per R3.

The danger tier is effectively unused

One btn-danger site across 769 buttons means destructive actions are being styled as ordinary primaries — e.g. "Delete" in analyze-mv-dialog is a plain btn-primary. This is a usage gap the codemod can't find on class alone: it needs a label-based sweep (Delete / Remove / Discard / Reset) to surface destructive actions that should carry .is-danger. Recommend adding that as a second enumeration pass.

5 · What goes back to the dev

Two adjustments to the codemod / lint rule

1 · Honour *ngIf. The 2+-primaries check over-counts mutually-exclusive buttons (expert-named-group is a false positive). The lint rule must only count buttons that can render simultaneously.
2 · Add a label sweep for danger. Class-based scanning misses destructive actions mis-styled as primary. Flag buttons whose label matches the destructive set for .is-danger review.

2 · Context → Role → Class

The mapping the spec is missing. Pick the row that matches where the action lives; the class column is the answer.

Context / placement Example Role Class Rule
Dialog footer — confirm Save · Create · OK Primary .btn-primary Exactly one per dialog.

4 · Flags — docs vs. shipped code

Where the table can't be filled in cleanly because the spec and the SCSS disagree. Resolve these before this drives implementation.

1 · .btn-light is undocumented

It has its own token family (--inet-button-light-*) and ships in production, but no design spec names it. It overlaps heavily with Secondary (both neutral, bordered).

Fix: name it as a 4th role (“raised neutral”) with a clear job, or fold it into Secondary and retire the class.

2 · .btn-default isn't a ghost at rest

The token --inet-button-default-border-color is transparent and the docs say “ghost at rest, no persistent outline.” But the selector hardcodes border:1px solid var(--inet-default-border-color) — a visible border.

Fix: decide ghost vs. light-outline and make the selector honour its own token.

3 · Danger is under-tokenized

There is no --inet-button-danger-* family. The selector pulls semantic tokens directly: a neutral rest border, and a hover that flips to full red while text stays dark maroon — a low-contrast hover.

Fix: add a danger button token family; raise hover contrast (white text on red, or red text on soft).

4 · Icon buttons have no visual contract

.btn-icon exists but only sets flex: 0 1 4em inside input-groups — no size, padding, or hover spec. Above it borrows .btn-light-no-bg to look right.

Fix: give .btn-icon a real square spec (size, centering, borderless-till-hover) and document it.

5 · Recommended Consolidation

The Figma-pattern target: 3 emphasis tiers + 2 modifiers. Neutral buttons step down by fill weight (accent → subtle gray → transparent), not by border. Hover any button — these are live.

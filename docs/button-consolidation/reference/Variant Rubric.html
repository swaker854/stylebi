Button Variant Rubric

The rules I apply to each flagged call-site once the enumeration inventory lands. Each judgment case from the Consolidation Plan §6 is written here as an explicit if → then, a default, and the lint assertion it maps to — so resolving the inventory is mechanical, and the lint rule and worksheet read from one source.

applies to: Consolidation Plan §6 feeds: §5 worksheet + lint rule default when unsure → Ghost

The one law

Exactly one Primary per scope. Never two.

Primary marks the action that advances the scope's purpose. If you can't say which single action that is, the answer is usually that there's no primary — not two.

A "scope" is: one dialog/modal footer · one page-header action region · one toolbar · one card or panel with its own actions. Nested panels each get their own scope (and may each have one primary).

Rules

R1Picking the Primarywhen 2+ primaries found

When a scope has multiple .btn-primary, demote until one remains — or none.

One action clearly completes / confirms the scope's purpose (Save, Create, OK, Apply)?
it stays primary; rest → secondary/ghost
The candidates are parallel choices of equal weight (SVG vs PNG, Day vs Week)?
all → secondary; scope has no primary
One of those parallel choices is the marked default (defaultFocus, most common path)?
default → primary, others → secondary
Tie-breaker: if no action confirms the scope and none is a marked default, make them all Secondary. A scope with no primary is valid; a scope with two is not.
LINTcount(.btn-primary) within a footer/header scope must be ≤ 1.
R2Dismiss is always Ghostcanonical: .btn-ghost

Cancel / Close / Dismiss / Back is always .btn-ghost — never secondary, never primary. It sits to the left of the affirmative action.

Button's role is to dismiss without committing (Cancel, Close, Not now)?
.btn-ghost
Why one variant: today dismiss is split across .btn-default and .btn-secondary (e.g. image-format-select). Pinning it to Ghost removes a whole class of inconsistency in one rule.
LINTa button whose label matches the dismiss set must use .btn-ghost.
R3Danger: CTA vs. inlinenever blind-replace

Two destructive forms, chosen by placement, not by the word "delete".

Is it the affirmative/confirm action of a destructive dialog (the thing the dialog exists to do)?
.btn-primary.is-danger
Is it an inline / row / toolbar destructive action among other actions?
.btn-ghost.is-danger
Tie-breaker: if it occupies the primary slot of a footer → CTA form. Otherwise → inline form. The danger CTA replaces the primary (R1 still holds: one emphasis action).
LINTflag bare .btn-danger for manual review; it must resolve to .is-danger on primary or ghost.
R4Secondary vs. Ghostdefault → Ghost

This is the subtle one. Ghost is the default for supporting actions. Secondary is rationed — promote only for a reason.

Is it the single most prominent action in a region that has no primary (e.g. a header whose only action is "Import")?
.btn-secondary
Does it pair against a primary as the clear alternative that needs weight to be seen?
.btn-secondary
Everything else — routine, repeated, or low-stakes supporting actions.
.btn-ghost
Budget & tie-breaker: aim for at most one Secondary per scope. When genuinely unsure between the two, choose Ghost — under-emphasis is cheaper to fix than a flat hierarchy.
LINTwarn on ≥ 2 .btn-secondary in one scope (soft — review, not block).
R5Icon buttons are square Ghosts.btn-ghost.btn-icon

Every icon-only button is .btn-ghost.btn-icon: transparent at rest, hover-fill, 1:1. No bordered icon buttons, no borrowed .btn-light-no-bg.

Icon-only, no text label (toolbar action, row ⋮, close ✕)?
.btn-ghost.btn-icon
LINTicon-only buttons must carry .btn-icon and resolve to the ghost tier.
